A2A 流式编排 设计

把 agent turn 的编排从「一个模型临场发挥」拆成两套各司其职的范式:workflow(冻结红线的确定性子程序工具)+ A2A 流式编排(human&agentic 协同的即时编排)。原语不是独立引擎的部件,而是 pydantic-ai capability → A2A card 投影。本文取代 turn-as-graph 报告里被否的「给 workflow kernel 加 DAG」路线。

⚠️ 取代声明。本文取代 docs/turn-as-graph-design.html 里的 P0 路线(给 workflow kernel 加 DAG/条件分支)——那条会动红线,已废。新路线:graph 编排走 A2A 流式编排,不扩 workflow。turn-as-graph 报告的四课题(智力颗粒度/全自动/记忆组件/硬编码多专项)仍有效,作为本设计的背景语境,但落地机制全部重定向到 A2A + capability 投影。

§1两范式(彻底分清,别混)

这是整个设计的地基。两套范式对立、各管一摊,混在一起就是过去几版设计反复出错的根源。

维度workflow(冻结红线)流式编排(graph 走这条)
本质给单一高智力 agent 的工具:封装让该 agent 做固定、完整、代码级编排(写 DSL/scripts,如 CC 的 workflow),扩展其执行能力human & agentic 协同:即时、流式、反应式地编排多 agent session
计划时机先全计划(agent 写完整脚本)边走边编(随结果涌现)
下一步谁决kernel 确定执行(run/pipeline/loop)MVP=人决;post-MVP=agentic
底层执行subagent(有限 nesting)、有结束、内部小循环判断A2A peer(fork/分支,各带 session/memory scope)
可改性可改脚本,但已跑部分不可热重载(像 cache)每段可重编、fork 可发散/收敛
独立性抽象范式 + DSL/scripts,相对独立迭代依赖 A2A mesh + capability 装配
红线不动,不加 DAG/条件分支—
红线:workflow 全程不动。它现在是、且只应是「agent 写完整确定性脚本 → kernel 执行」的唯一验证过的 tools 范式,扩展单 agent 的确定性执行能力。graph 编排不扩 workflow 内核。workflow 在流式编排里可被当作一个确定性子程序原语(agent 调 v2_workflow_run),但那是工具选择,不是编排底座。
两套范式管两种活:程序能完全预先指定→ workflow(agent 写死脚本跑);程序随结果涌现→ 流式编排(人/agent 即时编)。一个 main agent 可以两个都用——甩一段确定子程序给 workflow,外层用流式编排反应式调度。底座是 A2A,不是 workflow。

§2A2A mesh 地基(已通电)

流式编排的底座是本轮已落地的 A2A 内部 mesh(6 commit)。native/main 自成 A2A 节点,可互发现 + 互消费。这套 mesh 对任意 AgentSpec 泛化——加 agent = 加 yaml 条目,自动入 card/catalog。

关键性质:consumed agent = peer,非 subagent。它带全套自己 capability(不剥),跑在自己 agent_id scope(memory 各写各的)。R1(workflow 子 agent 零 writer)是另一条轴,不触发。这让 mesh 里的每个 agent 都是可承担编排角色的对等节点——流式编排的前提。

§3核心原则:原语 = capability → card 投影

这是本设计最关键的一句。原语不是独立编排引擎的部件,而是 agent 的 capability;A2A card 是它的声明面,project 自 pydantic-ai 的 capability 装配。单一真源 = capability 装配;card = 投影;catalog = 发现。无独立原语注册表,不造编排引擎。

§4流式编排 MVP(human-driven fork-explore)

流式编排是 human & agentic 协同。MVP 不设 agentic 入口,由 human 编排——人看当前 turn 结果,人决定 fork 几路、各探什么方向,agent 只在各 fork 上执行。引擎是人,不是 LLM。agentic 自编排(LLM 自决 fork/分段)是 post-MVP。

# 最小颗粒:基于当前 turn 结果 → fork session → 异步探索不同方向 session S · turn N 产出结果 │ 人看 result,决定探 3 方向 ├─ fork → S·a(async 探 A,agent=native)─┐ ├─ fork → S·b(async 探 B,agent=main) ├ session 组 = {S, S·a, S·b, S·c} └─ fork → S·c(async 探 C,agent=reader)─┘ 各 fork 异步跑,人观察 │ 人看 a/b/c,S·b 有戏 → 据「即时新需求」再编一段 ├─ S·b fork → S·b1, S·b2 ← 续 turn ... │ 人收敛:挑/合/弃,merge 回主线

本体循环(你描述的那个)

编排一小段 :人/agent 据 任务 + 已有结果,决定这段调谁、探什么 执行 :各 fork 的 agent 作 peer 跑(v2_a2a_call / 各自 turn) 得 session 组:fork 树(parent + 分支,可能不同 agent 参与) 即时新需求 :据执行结果(segment 的产出)涌现新方向 再编一段 :人据新需求 fork/续/换 agent 续 turn :同一逻辑 turn 继续循环(单 turn 内续 / 跨 turn resume)
最基础的编排就是 fork-explore:你现在用 agent 干活,干到一半想"要是走另一条路呢"——fork 出去异步探,几条路并行跑,你看着挑。CC/Cursor 都有这能力。AO2 的 fork_session(IT2)是种子,MVP 要把它升级成「一对多 + 指方向 + 指 agent + 异步并行」,配上人控 fork 树的 TUI 面。
MVP 不需要 agentic 编排引擎。「即时编排」在人驱阶段 = 人读 catalog(看各 agent card 声明的原语 affordance)+ 人用 control 面原语(compare/select/steer)操作 fork 树。agentic 入口(agent 自决 fork/分段)留 post-MVP——那时 agent 自己调 ForkCapability 等 primitive-capability。

§5handoff 难点:父节点状态 → 新 agent 继续

A2A agent 是对等 peer(各自 profile / 工具集 / memory scope / 模型)。"继续"不是 copy 一份 message——父节点对话是在父 agent 的 framing下产生的,原样塞给子 agent 会错位(工具调用引用子 agent 没有的工具、语境是父的 system prompt)。关键分解:把"状态"拆三层,只有一层真要交接。

状态层例子跨 agent 交接
material(物化)改的代码 / 文件 / artifact自动——共享 workspace(repo 工作树),父改的文件子 agent 直接看得见
conversational(会话语义)探了啥 / 决定了啥 / 关键发现要交接(难点在这)
memory(沉淀)累积记忆per-agent scope,跨读 opt-in(defer)
物化层因 workspace 共享而免费转移——真问题收窄到:会话语义层怎么从父 agent 交到子 agent。(若 fork 要物化隔离探索,每个 fork 配 git worktree,material 也 fork——这是 worktree 原语,另一条线。)

MVP:human-authored handoff(绕开自动交接)

MVP 人编——人读父(native)turn 结果,人写子 fork 的初始 prompt("native 探了 X 发现 Y,main 你接着探 Z")。人就是 handoff synthesizer,续接 prompt = 交接物。零自动状态转移机制。正契合"MVP 由 human 编排"。

post-MVP:自动交接方案空间(真·难点)

方案机制权衡
handoff summaryLLM 综合父状态成结构化摘要 → 子 fresh 起跑带此摘要agent-agnostic、profile/工具安全;损真 + 一次 LLM 开销
raw history 透传父 message_history 喂子 run(message_history=...)文本可移植;工具集不同时崩(同 registry 可,专项白名单不可)
session-group 共享态turn/fork-group 的结构化 KV,父写子读解耦任何 agent;要新建存储
A2A Task contextTask 带 history+artifacts+state,message/send 带上下文协议原生;吃 task 状态机 defer
实操大概率 handoff summary + workspace 物化 起步,session-group 共享态 / A2A Task context 随 task 状态机 defer 一起上。
