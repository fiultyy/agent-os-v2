① 为什么是这样:claw × Claude Code 取长补短

底层事实:claw(openclaw)与 Claude Code 对 LLM 是同一种 context 架构 —— system + tools[] + messages[] 三件套。差异只在 prompt 组装、cache 策略、内置 tools。AO2 不重发明架构,而是厘清两家强项并取长补短。

🦅从 claw 抄

boundary 语义层 用户指令进 stable prefix 固定文件顺序(字节稳定) per-file 截断 组装 hash 缓存 断点反向预算

强项:prompt 组装工程化、cache 友好、跨轮稳定。

🤖从 Claude Code 抄

5 条软件工程纪律(模型锚定) 易变首块单独不缓存 context-mgmt「够信息就动」

强项:纪律段锚定模型行为,实测 RL 背书。

❌两边都否决

CC messages 末块注入(失 cache) CC tools=0 前缀覆盖(不可移植) claw 71K 字膨胀(纪律被稀释) 80 字 micro-manifest(无 RL 背书) "不可覆盖"修辞(位置不是隔离)

弱项:不被采纳,带理由记录。

用户视角: AO2 不是从零造,而是站在两个成熟 harness 肩膀上挑最好的部分。每个决策都有"抄谁 / 否决谁 / 为什么"的出处。

⑤ 工程纪律详解:CC 5 条 + context-mgmt

这是 AO2 system prompt 里所有 provider 都受益的部分(即使无 cache)。抄自 Claude Code system prompt,作 stable 基线段默认注入。

## Engineering Discipline

Baseline rules for every turn in this harness:

1. Tools over shell. Prefer the purpose-built tool when one fits;
   fall back to shell only when no tool covers the task.
2. Parallelize independent calls. Make independent tool calls in the
   same response instead of sequentially.
3. Reference code precisely. Cite `file_path:line_number` so locations
   are verifiable and clickable.
4. Match surrounding style. Naming, idiom, comment density — code that
   reads like its neighbors.
5. Report faithfully. If a check failed, show the output; if a step
   was skipped, say so. No false success, no hedging.

When you have enough information to act, act. Don't re-derive established
facts or narrate options you won't pursue; if weighing a choice, give a
recommendation rather than an exhaustive survey.

① Tools over shell

优先用专门工具(grep/read/edit),shell 是兜底。让模型行为可预测、可审计。

② Parallelize

独立调用同一轮并发,而非串行。省 wall-clock。

③ file_path:line_number

引用代码精确到行,可点击可核实。杜绝"大概在那个文件"。

④ Match style

新代码读起来像邻居(命名/习惯/注释密度)。融入而非突兀。

⑤ Report faithfully

测试失败就报失败输出,跳步就说跳步。不假成功不绕弯。

+ context-mgmt

够信息就动,不重新推导已定事实,权衡时给推荐而非穷举。

A/B 旋钮(glm 等非 Claude 模型有效性无 ab,留 opt-out)

CC 5 条对 Claude 实测有效,但 glm(中文)无对照。AO2 提供 3 个旋钮做 A/B 后再固化:

  • EngineeringDisciplineCapability(enabled=False) — 关段
  • EngineeringDisciplineCapability(discipline_text="自定义") — 换文本
  • env AO2_DISCIPLINE_DISABLED=1 — 进程级关(组装层读一次)
位置诚实标注: 纪律段是 position=outermost(capability-tier 内居首),非 instructions 绝对首段。pydantic-ai 永远把 base instructions 放最前。不宣称"绝对首段"。
